# 기계 판독 가능한 단언 (assertions)

SKILL.md 의 **측정 단계**를 뒷받침한다 — 무슨 축을 훑고, 무엇을 근거로 인정하고, 어떤 도구로 뽑는지.

원 스펙 §6 은 CSS·레이아웃 PR 에 과적합돼 있었고, "수치 근거" 라는 문구가 정당한
비수치 발견을 게이트에서 차단했다. 이 파일이 그 두 결함을 정정한 결과다.

---

## (a) 축 선택 — 측정 전에 변경 유형을 판정한다

기본 매트릭스를 `1920,1440,1280,1024,768,390` × 로케일 N 으로 **고정하지 않는다.**
실제로 값을 하는 건 보통 한 축이고, 나머지는 순수 낭비다.

- 실측: i18n PR(`catalogDiscoveryViewModel.ts` · `teamName.ts`)에서 6 폭 스윕은 **0의 값**이었다.
- 실측: 레이아웃 PR(`line-clamp` · `min-height`)에서 로케일은 부수적이었다.
- 비용: 6 폭 × 로케일 2 = 12회 전체 플로우이고, 각 회차가 로그인 + 내비게이션이라
  **최소 6~12분**이다.

| 변경 유형 | 판정 신호 (diff) | 훑을 축 |
|---|---|---|
| 레이아웃·스타일 | `*.css` · `className=` · tailwind 폭·높이 유틸 · 스타일 토큰 diff | viewport × locale 대표값 + 측정값 |
| 상태·로직 | 상태 resolver · hook · 분기 함수 diff | 상태 매트릭스 + 전이 단언 |
| 문구·i18n | `messages/**` · `i18n/**` · `*ViewModel*` · 문자열 렌더 경로 diff | locale 전수 (viewport 1개면 충분) |
| 라우팅·딥링크 | 라우터 · search param diff | URL 파라미터 조합 |

- 판정에 안 걸리는 축은 **대표값 1개**만 잡는다.
- 전체 곱은 `--matrix full` 로 opt-in. `--viewports` / `--locales` 를 명시하면 그 값이 이긴다.
- 리포트에 **선택한 축과 그 근거**를 적는다:
  `Matrix: locales=ko,en x width=1440 (diff=i18n/view-model)`.
  축을 줄인 사실을 숨기면 리포트가 실제보다 강해 보인다.

## (b) 근거 형태 — 무엇을 "근거" 로 인정하는가

제목은 "수치 측정" 이 아니라 **"기계 판독 가능한 단언"** 이다.
금지 대상은 "숫자 없음" 이 아니라 **"단언으로 환원되지 않는 주관 서술"** 이다.

| 변경 성격 | 근거 형태 |
|---|---|
| 레이아웃·CSS | `getComputedStyle` · `getBoundingClientRect` spread · `scrollHeight>clientHeight` · 합성 before + viewport 표 |
| 상태·로직 | 상태 매트릭스와 각 조합의 관측 결과 · `data-*` 속성값 · `aria-*` 집합 |
| 문구·i18n | 규칙 + 데이터 전수 조사(N건 중 M건 위반) · 입력→렌더 결과 표 |
| 존재·어포던스 | 활성 컨트롤 개수 등 존재/부재 단언 |
| 접근성 | 역할·이름·대비비 검사기 출력 |

**실측 근거 3건** — 원 문구를 문자 그대로 집행했으면 앞의 둘이 게이트에서 막혔다.

1. **#2495 (한국어 조사 고정)** — `'{{skill}}' 을 붙이려면` 이 문자열에 조사를 박아 둬
   받침 없는 이름에서 전부 틀린다. 근거는 픽셀이 아니라 **문법 규칙 + 데이터 전수 조사**다:
   시드 스킬 40개의 한글 표시명이 `(ord(c)-0xAC00)%28 != 0` 기준으로 **40/40 받침 없음**.
   픽셀 0개인데 같은 런에서 등록한 레이아웃 결함보다 더 심각한 버그다.
2. **#2497 (i18n 폴백)** — `label_en` 을 빈 문자열로 바꾸면 영어 UI 에서 제목이
   **아무것도 렌더되지 않는다**(`label_ko` 에는 값이 있는데도). **있음/없음이지 크기가 아니다.**
3. **텍스트·상태 근거의 실제 형태** — `[data-banner-state]` 속성값(`waiting`/`multiComponent`) ·
   배너 `innerText` 의 부분문자열 포함/미포함(`'응대 품질 감사기' 포함` ·
   `'cs-response-quality-auditor' 미포함`) · `input[aria-label="Skill 검색"].value` 정확 일치 ·
   결과 행 개수 · `aria-pressed` 집합. 전부 기계 판독 가능하고 재현되지만 숫자가 아니다.

규칙을 "수치" 로 두면 발견이 막히거나, 더 나쁘게는 **픽셀 수치를 억지로 지어내게** 된다.

## (c) 측정 도구 (레이아웃·스타일 축)

- **잘림** — `el.scrollHeight > el.clientHeight`
- **적용된 스타일** — `getComputedStyle(el)` 의 대상 속성
- **정렬** — `getBoundingClientRect()` 로 형제 노드 좌표 **spread** 계산.
  실측: 세 카드 divider 의 y 좌표 spread `0.0px` 을 재서야 `min-height` 수정이
  정렬을 맞췄다고 확정됐다. 스크린샷으로는 판정 불가였다.
- **합성 before** — 노드를 `cloneNode(true)` 한 뒤 **이번 PR 이 바꾼 속성만 원복**하고
  (`min-height: 0` 등) 화면 밖에서 렌더해 잰다. **같은 실행 안에서 before/after 를
  나란히 얻는다.** 실측: 이 기법으로 `18.8px` 낭비를 정량화했고 그 표가 #2489 의 근거가 됐다.
- **경계 밀어보기** — 실데이터로 조건이 발동하지 않으면 텍스트를 극단값으로 주입한다.
  실측: 실제 팀명으로는 `title` 폴백이 안 떠서 **100자 이상**을 주입해서야
  clamp + tooltip 동작이 확인됐다.

## (d) 형제 비교 (peer baseline)

변경 대상이 **열거형 상태**(배너 상태 · 배지 종류 · 탭) 중 하나면,
**같은 컴포넌트의 나머지 값들과 동일 속성을 나란히 측정**해 새 값만 튀지 않는지 본다.

실측 — `blocked` 배너의 before 는 `border-tone-warn/40`, after 는 `border-tone-warn` 으로
**둘 다 정상 렌더**됐다. 색도 둘 다 warn 톤이라 before/after 축에서는 신호가 **0**이었다.
형제 7개와 나란히 놓아서야 혼자 불투명도 1.0(나머지 전부 0.4)인 게 드러났다(→ #2490).

| 배너 상태 | 테두리 계산값 |
|---|---|
| `waiting`·`noCards` | `oklab(0.568685 -0.0380889 -0.134901 / 0.4)` |
| `notFound`·`error` | `oklab(0.501289 0.156419 0.0856561 / 0.4)` |
| `linked` | `oklab(0.51262 -0.106587 0.0452466 / 0.4)` |
| **`blocked`** | **`rgb(153,101,15)` — 불투명도 1.0** |

**디자인 일관성 결함은 before/after 가 아니라 이 축에서만 드러난다.**

## (e) 지시-어포던스 일치

화면의 안내 문구가 특정 컨트롤을 지목하면(`[...]` · "…를 누르세요" · "Click …"),
그 이름의 **활성** 컨트롤이 실제로 존재하는지 단언한다.
배너 · 빈 상태 · 온보딩 단계처럼 "다음에 뭘 해야 하는지" 를 말하는 **모든 UI** 에 적용한다.

```js
// 안내 문구에서 대괄호 컨트롤명을 뽑아 그 이름의 활성 컨트롤을 센다
const wanted = [...banner.innerText.matchAll(/\[([^\]]+)\]/g)].map(m => m[1]);
const actionable = name => [...document.querySelectorAll('button, a[href], [role=button]')]
  .filter(el => (el.textContent||'').includes(name) && !el.disabled
                && el.getAttribute('aria-disabled') !== 'true').length;
```

**`!el.disabled` 가 핵심이다.** 실측: 같은 자리에 **비활성** `[이미 연결됨]` 버튼이 2개 있어서
"버튼이 있나" 로 세면 통과하고, **"누를 수 있는 버튼이 있나"** 로 세야 0개가 드러났다.

이 결함은 **레이아웃 지표를 전부 통과하고 스크린샷도 완벽히 정상으로 보인다** —
잘리지도, 어긋나지도 않았다. (c) 의 도구로는 전혀 잡히지 않는다.
같은 프로젝트에서 **두 런 연속** 나온 유형이다(#2481 본체 · #2492).

## (f) 셀렉터 규율

스킬 전체에 걸리는 규율이다 — 로그인 화면 한정이 아니다.

- 컨트롤은 **태그가 아니라 접근성 이름**으로 찾는다. 항상
  `button, a[href], [role=button], input[type=submit]` 를 **함께** 훑는다.
- 못 찾으면 "없다" 로 결론내기 전에 **`document.body.innerText` 에 그 문구가 있는지**
  먼저 본다. 문구는 있는데 셀렉터가 못 잡으면 그건 앱 결함이 아니라 **셀렉터 결함**이다.

실측 — 검증 대상 CTA 가 이랬다:

```html
<a href="/avatar-studio?addSkill=5eed00c2-...">내 아바타에 사용하기</a>
```

`locator("button", has_text="내 아바타에 사용하기")` → **0개**. 여기서 멈췄으면
"CTA 가 사라졌다" 는 오탐 이슈를 냈다. `has text: True` 를 보고 태그 가정이 틀렸음을 알아
빠져나왔다. 캐시(로그인 레시피)로는 이걸 못 막는다 — 캐시는 로그인 경로만 기억한다.

## (g) 응답 가로채기 (route interception)

(c) 의 기법은 전부 **이미 화면에 있는 것**을 재는 쪽이다. 경계 밀어보기도 DOM 텍스트 한정이다.
그런데 **오류 처리 · 권한 게이트 · 빈 상태 · 로딩 상태 PR 은 실데이터로 분기 도달이 불가능하다** —
시드 사용자는 항상 200 을 받는다.

대상 API 경로를 가로채 `403` / `5xx` / 빈 컬렉션 / `abort` 로 치환해 분기를 **강제 발현**시킨다.
대상 경로는 변경 파일이 호출하는 엔드포인트에서 유도한다.

```python
await pg.route("**/api/v1/avatar-system/me/avatar-cards*", handler)  # 403 / 500 / [] / abort
```

실측 — 검증 대상 4개 중 3개가 실데이터로 도달 불가였고, 이 한 줄로 6개 시나리오를
한 번에 훑어 그 결과가 곧 검증 결론이 됐다.

**가로채기는 브라우저 드라이버가 있어야만 가능**하므로, degraded 모드에서는 이 검사군을
통째로 `[SKIP]` 으로 선언한다 (`driver.md` 참고). 함정 두 가지도 그 파일에 있다.

## (h) 선행 조건 합성

대상 응답 **하나만** 바꿔서는 도달 불가한 경우가 흔하다. 선행 엔드포인트 응답까지 합성하는 것을 허용한다.

실측 — 중복 등록 409 팀명 문구 검증에서 주입할 텍스트 칸까지 가지도 못했다:

- 등록 버튼은 **미리보기 성공 전까지 비활성**이고,
- 시드의 데모 repo URL(`https://github.com/demo/…`)이 실재하지 않아 **미리보기가 항상 실패**하고,
- 통과해도 분야·태그가 **필수 입력**이라 그 전에 막힌다.

→ `/api/v1/submissions/preview`(성공) + `/api/v1/submissions`(409) **두 개를 합성**하고
폼 필수값을 채워야 대상 문구가 떴다. 그러고서야 로케일 2 × 페이로드 3 = 6조합을 확인했다:

| 페이로드 | ko | en |
|---|---|---|
| 한/영 둘 다 | 이미 **지원팀**에 등록… | already registered by **Support** |
| 영문명 공백 | 품질보증팀 | **품질보증팀**(한글 폴백) |
| 한글명 공백 | **Data Platform**(영문 폴백) | Data Platform |

**리포트에 `Synthetic:` 행 필수** — 어떤 엔드포인트·값을 합성했는지 적는다.
실데이터 검증과 스텁 검증이 구분되지 않으면 "verified" 가 실제보다 강해 보인다.

**합성이 유일한 길이라는 사실 자체가 신호다.** 시드에 한쪽 언어만 있는 팀
(`품질보증팀` · `Data Platform`)이 있는데도 발견 사유 칩은 로그인 사용자 **본인 팀**만 실어
폴백 경로가 영영 발동하지 않는다. 이건 결함이 아니라 **시드 갭**이므로 이슈 대신
리포트에 `[SKIP] 실데이터로 도달 불가 — 합성으로 검증` 으로 남기고,
반복되면 그때 시드 이슈로 올린다.

## (i) hit-test

측정 **직전에** 대상 요소가 다른 요소에 가려져 있지 않은지
`document.elementFromPoint()` 로 중심점 hit-test 한다.

가려진 요소는 "있지만 못 누른다" 라서 **사용자 입장에선 없는 것과 같다.**
실측: 네비게이션마다 다시 뜬 공지 팝업이 검증 대상 CTA 를 덮고 있었다
(`[2] 홈 공지 팝업 닫힘: True` → `[3] 공지 팝업 닫힘: False`).
오버레이 해제는 로그인 단계가 아니라 **모든 네비게이션 직후의 멱등 단계**이며,
해제를 가정하지 말고 단언한다.
