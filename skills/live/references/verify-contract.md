# PR 검증 공유 계약 (pr-verify contract)

`gh-verify:live` 와 `gh-verify:merged` 가 **함께** 지키는 계약이다. 두 스킬은 같은
슬롯(머지 직후 재검증)에 서로 다른 증명 대상을 담당한다 — live 는 **배포 동일성**(돌고 있는
앱이 그 커밋을 서빙하는가), merged 는 **소스 동일성**(신선한 클론이 그렇게 동작하는가).

이 파일이 계약의 유일한 사본이다. 어느 쪽 SKILL.md 에도 이 6줄을 복사해 두지 않는다 —
두 벌이 되면 갈라진다.

1. 머지된 PR 과 그 **merge commit** 을 해석한다.
2. **검증 대상이 그 커밋을 담고 있음을 다른 무엇보다 먼저 증명한다** — live = 서빙 체크아웃
   동일성, merged = 신선한 클론 동일성. 비교 기준은 `mergeCommit.oid` 이고 `headRefOid` 는
   쓰지 않는다(rebase/squash 가 재작성한다).
3. 주장은 diff 가 아니라 **PR·이슈의 Acceptance Criteria** 에서 뽑는다. diff 는 무엇이
   바뀌었는지만 말할 뿐 무엇이 참이어야 하는지는 말하지 않는다.
4. **주장 1건 = 기계 판독 가능한 단언 1건.** 제3자가 같은 절차로 같은 결과를 얻을 수 있어야
   한다.
5. 검증 전 단언이 하나라도 실패하면 **측정하지 않고 정지한다.** 부분 측정은 실제보다 강한
   리포트를 만든다.
6. 살아남은 발견은 **제자리에서 고치지 않고** `gh-issue:create` 로 새 이슈를 만든다. 두 스킬
   모두 소스에 대해 읽기 전용이다.

## 두 스킬의 분담

| | `gh-verify:live` | `gh-verify:merged` |
|---|---|---|
| 증명 대상 | 서빙 중인 체크아웃이 그 커밋인가 | 신선한 클론이 그렇게 동작하는가 |
| 전제 | 띄울 앱이 있다 (dev 서버 기동 중) | 앱이 없어도 된다 (shell · CLI · lib) |
| 측정 수단 | 브라우저 드라이버 · 뷰포트/로케일 매트릭스 | 프로젝트 테스트 러너 · 환경 변이 · 차등 |
| 쓰기 범위 | 소스는 읽기 전용, 앱 데이터에는 쓴다 | 임시 클론 밖에는 아무것도 쓰지 않는다 |

**배타적이지 않다.** 프론트엔드 PR 도 둘 다 돌 수 있다 — merged 로 유닛/빌드 재현성을,
live 로 화면을 본다.
