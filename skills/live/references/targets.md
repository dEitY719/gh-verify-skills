# 무엇을 검증할지 결정 (verification target)

SKILL.md Step 4 — 브라우저를 켜기 전에 검증 항목과 그 항목에 **도달하기 위한 선행 조건**(데이터
상태 · feature flag)을 PR 에서 뽑는 단계를 뒷받침한다.

## 1. 입력 우선순위

입력은 Step 2 에서 이미 받아 둔 `$PR_JSON` 이다 (`discovery.md` §2-1). **다시 받지 않는다** —
`title,body,files,mergeCommit,headRefOid,closingIssuesReferences` 가 그 한 번에 다 들어 있다.

| 순위 | 원천 | 뽑는 것 |
|---|---|---|
| 1 | `Closes #N` 으로 연결된 **이슈의 Acceptance Criteria** | 체크·미체크 **무관** 전부 |
| 2 | PR 본문 `## Test plan` 의 **미체크(`- [ ]`)** 항목 | 미체크만 |
| 3 | 변경 파일 → 화면 경로 추론 | 진입점 라우트 |
| 4 | `AskUserQuestion` | 변경 파일 목록을 보여주고 확인 경로를 묻는다 |

**순서가 뒤집힌 근거** — 원 스펙은 Test plan 을 1순위로 뒀으나 실측에서 전제가 깨졌다.

| 관측 | 결과 |
|---|---|
| PR #2473 의 Test plan + AC 10개가 **전부 `- [x]`** | 2순위가 뽑는 항목 **0개** → 곧장 4순위 폴백 |
| 연결된 이슈 #2469 의 AC 6개는 **전부 `- [ ]`** | 그중 **4개가 그대로 라이브 검증 대상**, 실제로 짠 매트릭스와 1:1 일치 |

이유는 구조적이다. **이슈 AC 는 구현 전에 쓰이므로 미체크로 남고, PR Test plan 은 머지 시점에
채워져 비어 버린다.** AC 는 "무엇이 참이어야 하는가"라 체크 여부와 무관하게 재확인 대상이다.

**Test plan 을 2순위로 유지하는 근거** — 세 런에서 파싱이 적중했다. PR #2483 의 미체크 2줄이
정확히 수동 확인 항목이었고 **그 두 줄을 실행한 결과가 곧 파생 이슈 #2492** 였다. PR #2484 ·
PR #2476 도 미체크 항목이 정확히 1줄씩이었고 그 줄이 검증 범위 전체였다. 버리지 않는다.

### 1-1. `- [x]` 를 "통과"로 취급하지 않는다

체크는 **작성자의 주장**이지 라이브 검증 결과가 아니다. 그 주장을 독립 확인하는 것이 이 스킬의
존재 이유다. 1순위가 "체크·미체크 무관"인 것도 같은 이유다.

### 1-2. Test plan 신선도 대조

`gh:pr` 이 체크박스를 **PR 생성 시점**에 쓰고, 이후 리뷰 라운드에서 갱신되지 않는다.

| 실측 | 그 사이에 일어난 일 | Test plan |
|---|---|---|
| PR #2485 | 리뷰 후 커밋 2개 추가 | 그대로 |
| PR #2476 | 리베이스 2회 | 그대로 |

→ 미체크 항목을 **후보**로 삼되, **최종 diff 와 대조**해 이미 자동 검증된 것 / 사라진 것을
걸러낸다. PR #2476 은 우연히 유효했지만 그건 보장이 아니다.

## 2. 라우트 추론은 진입점까지 따라간다

- 라우트 파일(`src/routes/**` · `app/**/page.tsx` · `pages/**`)이면 그 경로로 직행
- 컴포넌트/CSS 면 심볼·클래스명을 역참조해 사용하는 라우트를 찾는다
  (예: `.toolbox-trend-reason` → `ToolboxTrendPanel.tsx` → `/trends`)
- **바뀐 파일 자신의 라우트가 아니라 그 화면으로 들어오는 경로가 시작점이다.**
  실측: 변경 파일은 `AvatarStudioPage.tsx` 인데 검증 진입점은 `/items/<id>` 상세 CTA 였다.

**파일→라우트 매핑만으로는 플로우형 검증에 불충분하다.** 이것이 1순위·2순위(사람이 적어 둔
진입점 포함 문장)를 추론보다 위에 두는 또 하나의 근거다.

## 3. 테스트 데이터 상태 발견

조건부 UI 는 **화면 경로만으로 아무것도 검증되지 않는다. 어느 계정으로 들어가느냐가 곧 어느
분기를 보느냐**다. §2-2(서빙 체크아웃)와 **같은 등급의 조용한 거짓 통과 방지 장치**다 —
그쪽은 *잘못된 코드*를 보는 것을 막고, 이쪽은 *코드의 일부만* 보고 전부 봤다고 착각하는 것을
막는다.

### 3-1. 절차

1. PR 변경 파일에서 **분기 조건**을 뽑는다 — 상태 resolver · `if` 사다리 · feature 조건
2. 각 분기를 만족하는 **데이터 상태**를 정의한다
3. 그 상태를 가진 계정/레코드를 **API 로 훑어 찾는다** — 시드 계정 목록 + `me/*` 엔드포인트 조합
4. 못 찾으면 만들거나, 그 분기를 `Unverified` 로 리포트한다 — **조용히 건너뛰지 않는다**

### 3-2. 실측

배너 상태가 5갈래(`noCards` / `noTasks` / `waiting` / `multiComponent` / `linked`)인 PR 에서,
23개 mock 계정에 순차 로그인해 `GET /api/v1/avatar-system/me/avatar-cards` 를 찍어 상태표를 만들었다.

| 계정 | 데이터 상태 | 검증한 분기 |
|---|---|---|
| `user21` | 카드 0장 | `noCards` |
| `user19` | 카드 1장, 역할 0 · 업무 0 | `noTasks` (핵심 신규 분기) |
| `user10` | 역할 1개인데 업무 0 | `noTasks` 변형 |
| `user13` | 업무 3개 카드 **+** 업무 0개 카드 | `waiting` ↔ `noTasks` 전환 |

`user13` 은 그 PR 의 핵심 설계 결정(업무 개수를 **선택된 카드** 기준으로 센다)을 검증하는
**유일한** 데이터 상태였다.

> **기본 계정으로만 로그인했으면 `waiting` 하나만 보고 통과로 끝났을 것 — 거짓 통과다.**

## 4. feature flag 선행 확인

대상 기능이 플래그·권한·역할·공개범위로 게이팅돼 있으면, 검증 전에 **그 게이트가 현재 환경에서
열려 있는지** 확인한다.

1. 변경 파일에서 플래그 키를 grep 해 뽑는다 — `useOrgFeatureEnabled("...")` · `useFeatureFlag` ·
   env gate
2. 플래그 조회 API(`GET /api/v1/feature-flags`) · 관리자 콘솔(`/admin/features`) · 시드로 현재
   상태를 확인한다
3. 꺼져 있으면 그건 **결함이 아니라 미검증**이다
4. **켜고 진행할지 / 정지할지를 `AskUserQuestion` 으로 묻는다** — 임의로 켜면 조직 설정을 바꾸는
   부작용이라 추측 금지 대상이다

**실측** — `avatar.use_in_my_avatar` 는 조직 전역 플래그이고 **서버 기본값이 꺼짐**이었다.
확인 없이 진행한 스크립트는 이렇게 끝났다.

```
[3] CTA 개수: 0
!! [내 아바타에 사용하기] CTA 없음
```

여기서 멈췄으면 **"CTA 가 사라졌다"는 틀린 이슈를 낼 뻔했다.** 플래그 API 를 찍어 이 스택에선
켜져 있음을 확인하고서야 진짜 원인(그 CTA 가 `<button>` 이 아니라 `<a href>` 였던 것)에
도달했다. 다른 런에서는 admin 으로 `/admin/features` 를 먼저 확인했고, 꺼져 있었다면 스킬이
CTA 를 못 찾고 "확인 대상 없음"으로 **조용히 통과**했을 상황이었다.

게이트 중 가장 값싼 것에 비해 오탐 방지 효과가 가장 크다.

## 5. Step 3 산출물

| 항목 | 내용 |
|---|---|
| `checks[]` | 1절에서 뽑은 검증 항목 + 각각의 원천(AC / Test plan / 추론 / 사용자) |
| `entry_routes[]` | 2절의 진입점 경로 |
| `fixtures[]` | 3절의 계정/레코드 → 분기 매핑 |
| `gates[]` | 4절의 플래그 키와 현재 상태(open / closed / asked) |
| `unverified[]` | 3-1 step 4 · 4절에서 도달 불가로 판정된 분기 — 리포트 `Unverified:` 행으로 나간다 |
