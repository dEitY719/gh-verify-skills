# Constraints (rationale) — for gh-verify:live

SKILL.md 본문은 이 항목들을 한 줄씩만 적는다. 근거는 여기 있다. 전부 **실제 실행에서
문제가 됐거나 값을 한 것**이다 — 출처는 `provenance.md`.

## 검증 전 단언 3종 — 하나라도 실패하면 측정하지 않는다

여섯 번의 손 실행에서 걸린 자리가 겹친다. 셋 다 **"화면은 정상으로 보이는데 검증이 무효"**
라는 한 가지 실패 클래스다. 이 스킬의 뼈대이고, 나머지(측정 도구 · 게이트)는 그 위에 얹는
층이다. 이 3종이 없으면 어떤 측정도 신뢰할 수 없다.

1. **서빙 체크아웃이 대상 커밋을 포함하는가** — 세 런에서 dev 서버가 작업 워크트리가 아닌
   다른 디렉터리에서 돌고 있었다. 우연히 같은 코드라 통과했지, 확인 절차가 없으면 조용히
   틀린다. **사람이 직접 시켜도 매번 빼먹었다** — 세 런 중 두 번은 검증을 끝낸 뒤에야
   확인을 안 했다는 걸 알았다. 그래서 하드 정지다.
2. **로케일/뷰포트 전환이 실제로 적용됐는가** — `localStorage.setItem('i18nextLng','ko')` 가
   아무 효과 없이 **정상 종료**했고, 두 로케일 런이 같은 영어 화면을 냈다. 그 상태로
   "ko/en 동일 문자열" 을 검증 결과로 보고할 뻔했다. 전환 실패는 소리 없이 통과한다.
3. **대상 요소가 오버레이에 가려지지 않았는가** — 공지 팝업이 검증 대상 CTA 를 덮고 있었다.
   가려진 요소는 "있지만 못 누른다" 라서 사용자 입장에선 없는 것과 같다.

## 서빙 체크아웃 불일치는 정지, dirty 는 경고

정지가 맞는 이유: 잘못된 코드를 검증하느니 멈추는 게 낫다. 반대로 dirty 워킹 트리는
**정지가 과하다** — Vite 는 HEAD 가 아니라 워킹 트리를 서빙(HMR)하므로 HEAD 가 맞아도
화면이 낡을 수 있지만, 사용자가 의도적으로 뭔가 얹어 놨을 수도 있다. 경고 + 리포트 명시가
맞다. 컨테이너 백엔드는 `devx_pr_verify_live_backend_identity.sh` 헬퍼를 통해 검증하며, verified면 계속 진행, mismatch면 즉시 정지(FAIL)한다. unverified인 경우에는 정지하지 않고 미검증 상태로 두되 구체적 근거와 이유를 리포트에 적는다.


## ancestry 비교는 `mergeCommit.oid` — `headRefOid` 금지

rebase/squash merge 는 head sha 를 base 에 남기지 않는다. `headRefOid` 로 비교하면
**정상적으로 머지되어 정상적으로 서빙 중인 상태에서 100% 오정지**한다. 세 PR 실측에서
전부 재현됐다. 위 항목이 하드 정지이므로, 잘못 구현하면 스킬이 그 레포에서 한 번도
성공하지 못한다. 머지 방식을 스킬이 알 필요는 없다 — `mergeCommit` 하나로 merge/rebase/
squash 세 경우가 다 덮이고, `null` 일 때만(미머지 PR) `headRefOid` 로 떨어진다.

## 소스는 읽기 전용, 앱 데이터는 쓰기 대상

**코드를 고치지 않는다.** 검증 중 원인이 보여도 손대고 싶어지는데, 읽기 전용 경계 덕분에
발견이 이슈로 온전히 남는다. 두 런에서 이 경계가 실제로 값을 했다.

그러나 "읽기 전용" 을 앱 데이터까지 주장하면 사실과 다르다. 한 런에서 생성 경로를
검증하려고 UI 로 **아바타 역할을 진짜로 만들었고**(`POST … 201` 두 건), 그 레코드는 dev DB
에 남아 있다. 회피 가능한 사고가 아니라 **검증에 필요한 행위**였다 — 만들어 보지 않으면
"생성 후 자동 펼침" 을 확인할 방법이 없다. 따라서:

- 이 스킬은 **dev/fake 스택 전용**이다. 공용 staging·운영에 대지 않는다.
- 대상이 로컬이 아니면 `--allow-remote-host` 없이는 정지한다. **로컬 판정은 표기법이 아니라
  주소 자체로 한다** — `localhost` · `127.0.0.0/8` 전체(`127.0.0.1` 뿐 아니라 `127.0.1.1` 등) ·
  `::1` · `[::1]` · `0.0.0.0` · `[::]` 를 모두 로컬로 본다. `127.0.0.1`/`localhost` 두 표기만
  허용하면 IPv6 루프백이나 `0.0.0.0` 바인딩으로 뜬 **흔한 dev 스택이 원격 취급**되어, 안전
  가드가 정작 일상 경로에서 `--allow-remote-host` 를 습관적으로 붙이게 만든다 — 가드가
  무력화되는 전형적인 경로다.
- 생성하는 레코드에는 **식별 가능한 접두사**를 붙인다(`검증용 … #<PR>`) — 사후에 골라내려면
  이것밖에 방법이 없다.
- 리포트 `Created:` 행에 남긴 것을 나열한다. 정리는 사용자 몫이어도 무엇이 남았는지는 알린다.

## 남의 서버를 죽이지 않는다

전제가 "서버는 이미 사용자가 띄워 둔 상태" 이므로 기본 동작은 "찾는다" 이지 "띄운다" 가
아니다. `--start` 로 **스킬이 직접 띄운** 프로세스만 스킬이 정리한다.

## 근거 게이트는 "수치" 가 아니라 "기계 판독 가능한 단언"

원 문구("수치 근거가 있다")를 문자 그대로 집행하면 실측에서 **더 심각한 버그 두 건이
차단됐다** — 한국어 조사 고정(#2495, 근거는 문법 규칙 + 시드 40건 전수 조사)과 빈
`label_en` 으로 인한 제목 미렌더(#2497, 있음/없음이지 크기가 아니다). 게다가 픽셀 수치를
억지로 지어내게 만드는 역효과가 있다. 걸러내려는 건 *숫자 없음*이 아니라 **제3자가 같은
절차로 같은 결과를 얻지 못하는 것**이다. "인상 비평 금지" 라는 원래 의도는 유지되고 근거
형태만 넓어진다.

## 자기 반증이 게이트보다 먼저

한 런에서 FAIL 로 뜬 4건이 **전부 위양성**이었고, 원 게이트 4개를 **전부 통과**했다 —
재현되고, 값이 있고, 중복 아니고, PR 이 만든 것처럼 보였다. 자동화했으면 남의 레포에
이슈 4건을 오등록했을 것이다. 진짜 원인은 전부 "지루한 설명"(하네스 버그 · 데이터 상태 ·
의도된 필터)이었고 인상 비평 필터로는 하나도 못 걸린다. 3건이 정확히 "다른 픽스처로 1회
더" 에서 걷혔다 — 비용은 실행 1회, 이득은 오등록 3건 방지.

## 이슈 본문은 재기술하지 않는다

`gh-issue:create` 가 본문 골격 · 라벨 SSOT 판정 · ai-metrics 푸터의 SSOT 다. 여기에
템플릿을 옮겨 적으면 그쪽이 바뀔 때 두 곳이 어긋난다. 이 스킬은 **게이트만** 책임진다.
위임해도 남는 건 레포측 기계적 함정뿐이다(없는 라벨 · classic Projects 의 `--add-label`
실패 · 보드 카드 동기화) — `findings.md` §6.

## 축소한 커버리지를 숨기지 않는다

기본 매트릭스를 6폭 × 로케일 N 으로 고정하면 실제로 값을 하는 한 축 외에는 전부 낭비다
(각 회차가 로그인 + 내비게이션이라 12셀이면 최소 6~12분). 그래서 축은 diff 가 정하고
전체 곱은 `--matrix full` opt-in 이다. 대신 **줄인 사실을 리포트에 적는다** —
`Matrix: 1440 x ko (1/12 cells)`. 같은 원칙이 `Unverified:` · `Synthetic:` · `Rejected:`
행에도 적용된다. 리포트가 실제보다 강해 보이면 다음 사람이 다시 검증하지 않는다.

## 자격증명은 어디에도 남기지 않는다 — `storage_state` 는 예외가 아니다

프로브 5회에 로그인 5회 반복은 낭비이므로 세션 재사용을 **허용한다**. 다만 `storage_state`
는 세션 쿠키 그 자체라 레시피 캐시에 두면 이 제약과 정면 충돌한다. 확정: **런 스코프 임시
파일에만 쓰고, 정상·실패 무관 종료 시 삭제하며, 리포트·로그·이슈 본문에 경로를 남기지
않는다.** 레시피 캐시(`.claude/pr-verify-live.json`)에는 자격증명이 들어가지 않는다.

**종료 시 삭제만으로는 부족하다.** `SIGKILL`·OOM·전원 차단이면 정리 트랩이 실행되지 않고
세션 쿠키가 파일시스템에 무기한 남는다. 트랩을 유일한 방어선으로 두지 않는다:

- 파일은 생성 시점에 **`umask 077`(mode 0600)** 로 만든다 — 트랩이 안 돌아도 소유자 외에는
  읽지 못한다.
- 경로를 **`pr-verify-live-<PR>-<pid>` 처럼 고정 규칙**으로 잡고, 스킬 **시작 시 같은 규칙의
  잔여 파일을 먼저 지운다**. 지난 실행이 강제 종료됐어도 다음 실행이 청소한다.
- 세션은 짧게 잡는다(그 실행 안에서만 유효). 다음 실행은 잔여 파일을 재사용하지 않고
  새로 로그인한다 — 재사용의 이득은 한 실행 안의 반복 프로브에서 나오지 실행 간에서 나오지 않는다.

## 추측 금지

포트 후보가 여럿일 때, 기동 명령을 못 찾았을 때, feature flag 가 꺼져 있을 때는
`AskUserQuestion` 으로 묻는다. 특히 플래그를 임의로 켜는 것은 **조직 설정을 바꾸는
부작용**이라 추측 대상이 아니다.
