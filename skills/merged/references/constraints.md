# Constraints (rationale) — for gh-verify:merged

SKILL.md 본문은 이 항목들을 한 줄씩만 적는다. 근거와 전체 목록은 여기 있다.

## NF-1 — 격리: 검증은 임시 클론 안에서만 일어난다

**사용자의 작업 트리·인덱스·스태시를 읽지도 쓰지도 않는다.** 이 스킬의 존재 이유가 "작업
트리가 검증을 오염시킨다" 이므로, 검증 중에 작업 트리를 조금이라도 대상으로 삼으면 스킬이
막으려던 실패를 스스로 재현한다.

허용되는 유일한 예외는 **F-3 의 비교 목적 읽기**다 — 클론과 작업 트리의 테스트 케이스 집합을
맞춰 보는 것. 그 예외조차 다음을 지킨다:

- 작업 트리에서는 **파일을 쓰지 않는다.** 케이스 이름은 collect-only 모드로 얻고, 그 모드가
  없으면 비교를 포기하고 `Unverified:` 로 적는다.
- `git -C <worktree> fetch` 도 하지 않는다 — refs/objects 를 늘리는 것도 쓰기다. 필요한
  커밋은 **클론 안에서** 원격을 붙여 받는다.
- 작업 트리의 브랜치·스태시·인덱스를 바꾸는 명령(`checkout` · `stash` · `add` · `worktree
  add`)은 어떤 경우에도 실행하지 않는다. `.before` 워크트리는 **클론 내부**에 만든다.

## NF-2 — 정리: 성공하면 지우고, 실패하면 남긴다

| 종료 상태 | 클론 | 이유 |
|---|---|---|
| `[OK]` / `[WARN]` | 정리 | 검증이 끝났고 근거는 리포트에 남았다 |
| `[FAIL]` | **남기고 경로 출력** | 정지 원인을 사후 조사하려면 그 트리가 있어야 한다 |
| `--clone-dir` 지정 | 남긴다 | 사용자가 위치를 못 박았다는 것은 다시 보겠다는 뜻이다 |

클론은 `mktemp -d "${TMPDIR:-/tmp}/pr-verify-merged-<PR>-XXXXXX"` 로 만든다. 고정 규칙 이름을
쓰는 이유는 강제 종료로 정리 트랩이 안 돌았을 때 **다음 실행이 같은 패턴의 잔여물을 찾아
안내**할 수 있게 하기 위해서다. 경로는 성공·실패 무관하게 리포트 `Clone:` 행에 적는다.

## NF-3 — 소프트 실패 경계

| 실패 | 처리 |
|---|---|
| F-2 단언(클론 실패 · HEAD 불일치) | **측정 없이 전체 정지** |
| F-3 단언(더러운 클론) | **측정 없이 전체 정지** |
| 테스트 러너 미탐지 | 정지 아님 — `Unverified:` 한 줄, AC 단언은 계속 |
| 환경 축 1개 실패 | 정지 아님 — 그 축만 `unverified`, 나머지 축 계속 |
| 차등 검증 불가 | 정지 아님 — 그 주장만 `unproven` / `n/a` |
| 이슈 생성 실패 | 정지 아님 — 본문 출력 + `[WARN]` |

경계를 이렇게 그은 이유: F-2/F-3 이 깨지면 **이후 모든 측정의 의미가 사라진다**(잘못된 트리를
재고 있는 것이다). 반면 축 하나가 못 도는 것은 커버리지가 줄어드는 것뿐이라, 줄었다는 사실을
리포트에 적으면 정직하게 남는다. 정지와 축소를 구분하지 않으면 둘 중 하나가 반드시 잘못
처리된다.

## NF-4 — 파괴적 명령 금지, deny 규칙 우회 금지

프로젝트가 `Bash(rm:*)` 같은 deny 규칙을 둘 수 있다(실측: `obsidian-para`). 정리 순서는:

1. 애초에 **`$TMPDIR` 아래 run-scoped 디렉터리**에 만든다 — 지우지 못해도 OS 가 수거한다.
2. 정리는 표준 경로 하나(`rm -rf "$CLONE"`)로만 시도한다.
3. 그 호출이 권한 시스템에 막히면 **거기서 멈춘다.** `find -delete` · `python -c
   'shutil.rmtree'` · `sh -c 'rm ...'` 같은 **위장 우회를 시도하지 않는다.** deny 규칙의 의도는
   "이 세션에서 파일을 지우지 마라" 이고, 다른 도구로 같은 일을 하는 것은 규칙 위반이다.
4. 막혔으면 리포트에 경로와 함께 남긴다:
   `Next: 임시 클론이 남아 있습니다 — <path> (삭제는 사용자 권한으로 직접 수행하세요)`

같은 원칙이 사용자 레포에도 적용된다 — 정리를 이유로 사용자의 파일을 지우는 일은 없다.

## 읽기 전용 경계 — 코드를 고치지 않는다

검증 중 원인이 보여도 손대지 않는다. 산출물은 이슈다. 이 경계 덕분에 발견이 온전히 남고,
"고치면서 검증" 이 만들어 내는 자기 확인(내가 고친 것을 내가 통과시킴)이 생기지 않는다.
이슈 본문·라벨·ai-metrics 는 `gh-issue:create` 가 SSOT — 여기에 템플릿을 옮겨 적지 않는다.

## Error Cases

소프트 실패(정지 아님) 처리는 NF-3 을 그대로 따른다 — 테스트 러너 미탐지 · 환경 축 1개 실패 ·
`gh-issue:create` 실패는 여기서 다시 적지 않는다. 아래는 NF-3 표에 없는, 정지로 이어지는
구체 상황이다.

| 상황 | 처리 |
|---|---|
| PR 이 `MERGED` 가 아님 | `[FAIL] PR #N state=<X> — 머지된 PR 이 대상이다` + 정지. escape hatch 없음 — 미머지 검증은 `gh-verify:live` 소관이다 |
| `mergeCommit.oid` 가 null (미머지 · 삭제됨) | 정지. PR URL 을 출력해 사용자가 상태를 직접 보게 한다 |
| 클론 실패 (디스크 · 권한 · 커밋 미도달) | `[FAIL]` + git 의 원인 문자열을 **그대로** 출력. 부분 상태를 남기지 않는다(만들다 만 디렉터리는 정리하고, 정리가 막히면 경로 출력) |
| 클론 워킹 트리가 더러움 | 정지 — 검증이 오염된다. `git status --porcelain` 출력을 함께 싣는다 |
| 정리가 프로젝트 deny 규칙에 막힘 | 경로를 출력하고 사용자에게 위임. **우회 금지** (NF-4) |

## 추측 금지

주장 출처가 없을 때(이슈 AC 도 Test plan 도 커밋 `검증:` 줄도 없을 때), 러너 후보가 여럿일
때는 `AskUserQuestion` 으로 묻는다. 못 찾은 값을 지어내지 않고, 축소한 커버리지를 숨기지
않는다.
