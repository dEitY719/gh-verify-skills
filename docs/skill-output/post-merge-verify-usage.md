# post-merge-verify 사용 결과

> **한 줄 요약** — 머지된 PR 을 받아 구현 탭을 닫고 main 을 리베이스한 뒤 검증 세션을 여는 디스패치를 수행합니다.

```
머지된 PR  ──▶  /gh-verify:post-merge-verify  ──▶  main 리베이스 + 검증 세션 오픈
```

## 1. 실행한 명령

```
/gh-verify:post-merge-verify <PR#>
```

## 2. 입력

- 대상 후보 PR — `dEitY719/dotfiles#1670` (MERGED)
- 의존 도구 — `herdr` (세션 오픈), repo 별 검증 스킬 레지스트리

## 3. 결과

**실행하지 않았다 — 무인 실행에 안전한 경로가 없다.** 이 스킬은 GitHub 에는 쓰지 않지만
사용자의 로컬 작업 환경을 바꾼다. 실측한 상태는 다음과 같다.

| 항목 | 실측 |
|---|---|
| `herdr` 설치 | 설치됨 (`~/.local/bin/herdr`) — 도구는 갖춰져 있다 |
| dry-run 플래그 | `references/help.md` 의 플래그 표에 **없음** — 미리보기 경로가 존재하지 않는다 |

부작용은 세 가지다: 현재 구현 탭을 **닫고**, 로컬 `main` 을 **리베이스**하고, 새 herdr
세션을 **띄운다**. 셋 다 사용자의 열린 작업 상태를 건드리므로 문서 생성 작업 도중에
무인으로 실행할 성질이 아니다.

이 스킬은 그 자체가 검증자가 아니라 **디스패치 전용**이라는 점도 함께 봐야 한다.
실제 검증은 이 스킬이 열어 주는 세션에서 `merged` 또는 `live` 가 수행하며, 그쪽의 실행
기록은 [merged-usage.md](merged-usage.md) 에 실측으로 남아 있다.
