# live 사용 결과

> **한 줄 요약** — 실행 중인 앱과 PR 번호를 받아 서빙 체크아웃이 target commit 임을 증명한 검증 리포트를 생성합니다.

```
실행 중인 앱 + PR 번호  ──▶  /gh-verify:live  ──▶  [OK]/[WARN]/[FAIL] 리포트
```

## 1. 실행한 명령

```
/gh-verify:live <PR#> [--url <base>] [--no-issue] [--no-comment]
```

## 2. 입력

- 대상 PR — `dEitY719/dotfiles#1670`
- 필수 전제 — **target commit 을 서빙 중인 개발 앱**

## 3. 결과

**실행하지 못했다 — 전제 조건 미충족.** 이 스킬은 "이미 떠 있는 앱이 정말 그 커밋을
서빙하는가"를 먼저 단언하고, 그 단언이 실패하면 **측정하지 않고 정지**하는 계약이다.
아래는 그 전제가 없다는 실측이다.

| 후보 repo | 서빙 가능 여부 | 근거 (실측) |
|---|---|---|
| `dEitY719/dotfiles` | 불가 | 셸 설정 repo — 저장소 루트에 `package.json` 자체가 없다 |
| `dEitY719/gh-verify-skills` | 불가 | `package.json` 에 `scripts` 키가 아예 없다 (스킬 마켓플레이스) |

두 repo 모두 띄울 앱이 없으므로 `live` 의 서빙 체크아웃 신원 증명은 성립하지 않는다.
이것이 이 repo 가 자매 스킬 `merged` 를 함께 묶어 두는 이유다 — 같은 머지 후 슬롯에서
앱이 없는 repo 는 신선한 클론 신원으로 증명한다. 실제 실행 기록은
[merged-usage.md](merged-usage.md) 를 참고하라.

없는 앱에 대한 검증 결과를 지어내는 것은 이 스킬이 명시적으로 금지하는 실패 모드
("측정하지 않은 통과를 보고하지 않는다") 그 자체이므로, 수치를 채우지 않고 비워 둔다.
